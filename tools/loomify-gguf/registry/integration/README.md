# Provider registration and emission integration

This test loads generated bytecode from the actual Qwen decode-control kernel and
GGML scale/min motif sources, snapshots them through the provider registry, and
links a newly emitted device consumer and runs canonical final template selection.
It checks the kernel export metadata,
consumer output stores and actual motif dependency body, then reloads text and
bytecode in fresh contexts after releasing all original provider/compiler owners.
It also checks that omitting the real motif provider fails canonical validation
and a valid retry works. Native linkage can retain open template applications;
the missing-provider case then invokes public final template selection.

Run from the repository root with the project Bazel/toolchain configuration:

```sh
bazel test //tools/loomify-gguf/registry/integration:provider_emission_test
```

For the combined focused gate, also run `framework_test`, `module_loader_test`,
`provider_registry_test` and `consumer_emitter_test` from their adjacent packages.
The fixture files are declared test data and loaded through Bazel runfiles; model
weights and GPU execution are unnecessary. Passing proves structural/linkage and
ownership behavior, not numerical kernel execution or command-program launch.
